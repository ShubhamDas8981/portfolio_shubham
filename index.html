01 / HOW I THINK

Good AI isn't just about what it can do.
It's about what it shouldn't.

I care about the moment after a model responds. Is the output valid? Is the action allowed? Is the evidence strong enough? And if it isn't — does the system know how to stop?

That thinking shapes the systems I build: structured outputs, deterministic policy checks, privacy controls, evaluation suites and human review paths. The model contributes intelligence. The surrounding system earns trust.

I also care about the people using the workflow. An automation is only useful when it removes friction without hiding responsibility.

01 / CONTROL

Bound the model

Typed schemas, input and output guards, policy checks and explicit failure paths.

02 / EVIDENCE

Test the behaviour

Offline evaluation sets and automated tests before trusting a workflow in production.

03 / PEOPLE

Design the handoff

When confidence or policy says stop, send useful context to a human — not a guess to a customer.

01 — INSURTECH / CLAIMS AUTOMATION

OPD Claim Engine

An AI claims assistant for employee health bills. Employees submit a bill; the pipeline extracts and audits it. Clean, small claims can move forward instantly. Doubtful cases go to human review. Money decisions stay with fixed rules and the database — not the LLM.

Engineering details: FastAPI publishes jobs to Kafka; workers extract with Groq, validate strict Pydantic schemas, apply policy checks, mask PII and create a HubSpot handoff when needed.
